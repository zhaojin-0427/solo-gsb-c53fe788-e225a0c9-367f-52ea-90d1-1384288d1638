# 🎛 灯光渐变时间轴（Lighting Fade Timeline）

供灯光师排演使用的“灯光渐变时间轴” Web 应用。浏览器中以原生 JavaScript 展示
各灯具通道（DMX 通道，取值 0～255）的提示项时间轴与实时读数，后端使用
Python + FastAPI + SQLite 保存工程。

## 功能概览

- **提示项管理**：新建 / 编辑 / 删除提示项，逐项设置灯具、通道、目标值（0～255
  整数）与渐变时长（非负整数毫秒；`0` 表示立即切换）。
- **两种起步方式**：
  - 绝对时间：非负整数毫秒；
  - 引用另一项的 **开始** 或 **结束**，再加非负整数毫秒偏移。
- **保存校验（失败不改变原工程）**：
  - 引用的提示项不存在（缺失引用）→ 拒绝；
  - 引用链存在环（含自引用）→ 拒绝，并给出环路径；
  - 删除仍被其他项引用的提示项 → 拒绝；
  - 同一灯具同一通道在同一实际时刻已有一项起步 → 拒绝；
  - 任何校验失败都在同一数据库事务中回滚，原工程保持不变。
- **自动重算**：保存成功后，按引用 DAG 拓扑顺序重算全部实际开始/结束时刻。
- **渐变求值模型**：
  - 各通道初值为 `0`；
  - 新渐变从起步时刻上一渐变的 **未取整（精确分数）值** 接续，做线性渐变；
  - 零时长立即切换；后开始的提示项会 **打断** 尚未结束的渐变，被打断项在
    时间轴上用红框 + 红色斜纹/覆盖区标出；
  - 支持任意 **非负小数毫秒** 时刻求值（如 `1.5`、`5/3`，可含分数，
    端到端以 `fractions.Fraction` 精确处理，绝不截断小数）；显示值
    **四舍五入，恰好 0.5 向上**（界面同时显示精确分数值）。
- **时间轴界面**：
  - 每灯具通道一条泳道，色块表示渐变、窄竖条表示立即切换；
  - **在时间轴上按住拖动**移动播放头，**播放 / 暂停 / 归零**，或输入毫秒
    跳转（均支持小数毫秒，播放头时间全程不取整）；
  - 读数始终来自后端按该时刻的精确求值：播放、拖动、跳转产生的时刻从
    内部状态与跳转输入框 **原样** 送往 `/eval`（回显、去重、节流末次补发
    均不做任何固定位数舍入），播放时限流约 12 次/秒，暂停 / 跳转 /
    拖动结束都会立即补发当前时刻，因此 **跳转/拖动/播放的读数与直接
    对同一时刻调用 `/eval` 完全相同**；
  - **读数只对“同一工程 + 同一版数据 + 同一时刻”缓存**：切换工程，或
    提示项成功新增 / 修改 / 删除后，即使播放头时刻完全未变，也会作废旧
    读数并对当前工程数据重新调用 `/eval`；在途的旧响应（属于旧工程、
    旧数据，或播放头已移开后的 **旧时刻**）一律作废——成功不覆盖当前
    读数、失败不清屏不弹错——并按需补发当前时刻的求值。切到空工程立即
    清空旧通道；工程切换详情在途期间播放头跳走时，旧时刻读数会立即撤下，
    详情失败回退后按当前时刻补算；当前工程当前时刻求值失败时清空旧读数
    并弹出错误提示；**保存被后端拒绝时工程数据与读数均保持原样**；
  - **连续切换工程不会错配**：每次切换都为详情请求发放递增序号，只有
    最后一次选择的响应可以应用（工程 ID 相同也无法蒙混——A→B→A 中较早
    的 A 响应同样被丢弃）；过期详情的成功或失败都不改动当前页面；最后
    一次选择加载失败时弹出提示并回退到仍在屏上的工程，不会留下错配读数；
    详情在途期间求值被挂起，详情落地后才按当前时刻求值，泳道、编辑区与
    读数始终属于同一个工程；
  - **等待期间的读数只在“屏上工程 + 原时刻”下有效**：详情在途（或加载
    失败已回退）期间，若播放头仍停在原时刻，屏上读数继续有效；一旦跳到 /
    拖到 / 播放到新时刻（如 A 已显示 t0、选 B 后播放头跳到 t1），t0 的
    旧读数立即撤下，绝不会留在 t1 旁；此时若 B 详情失败、上下文回退 A，
    会按 **当前播放头 t1** 重新求值（得到 A@t1），而不是保留 A@t0。
    在途求值同样按“工程 + 数据代次 + 时刻”核对：播放头移动后才返回的
    **旧时刻响应（无论成功或失败）一律作废**，不得当作新时刻读数显示，
    并按需补发当前时刻的求值；当前工程的求值失败则清空读数并弹出错误
    提示；
  - 选中提示项后，时间轴以紫色描边标出其完整 **引用链**（上游依赖与下游引用者），
    编辑面板可点击引用链上的 `#编号` 跳转；
  - 读数卡片标注“渐变中 / 保持”状态；若当前渐变之后将被打断，给出提示。
- **跨工程片段移植**：在源工程勾选多个提示项，指定另一个工程与非负整数毫秒
  落点后提交；所选项连同 **全部上游引用项作为一批** 移植（共享祖先只移植一次），
  片段 **最早实际起步**（先解析引用得到）对齐落点，相对时差、渐变时长与引用
  开始/结束语义全部保持。提交成功后自动打开目标工程，时间轴上以青色描边 / 角标
  标出移植项并标注原 `#编号`，侧栏横幅列出 **原 ID → 新 ID** 对应；空选择、
  无效提示项 / 工程、源与目标相同，以及合并后目标工程上的同通道同刻冲突都会被
  拒绝且两边数据不变。

## 一键启动（Docker Compose）

```bash
docker compose up -d --build
```

启动后浏览器访问：

- 应用界面：<http://localhost:8000/>
- API 文档（Swagger UI）：<http://localhost:8000/docs>
- 健康检查：<http://localhost:8000/api/health>

### 访问连续切换后的工程时间轴

打开 <http://localhost:8000/> 后，左上角“工程”下拉框默认选中演示工程。
在“工程”下拉框中 **快速连续切换多个工程**（也可用“＋ 新工程”新建空工程
再切换）：无论详情接口响应谁先谁后，页面最终只呈现 **最后一次选择** 的
工程——泳道、编辑区与通道读数始终属于同一工程，读数对应该工程在当前
播放头时刻的精确求值；切到空工程会立即清空旧通道。若最后一次选择加载
失败（如下拉框中工程已被删除），会弹出错误提示并回退到仍在屏上的工程，
不会显示错配读数。

还可核对“等待期间跳播放头”的情形：先切到一个会加载失败的工程（例如
在另一个浏览器标签中删除某个工程后，再在本页下拉框选中它），在详情
**尚未返回时把播放头拖到 / 跳到另一时刻**——原工程旧时刻的读数会立刻
撤下而不是停在新播放头旁；加载失败回退后，读数按新时刻对原工程重新
求值。正常的工程切换在详情落地后同样只按当前时刻求值。

### 访问跨工程移植结果

1. 在左上角“工程”下拉框选中 **源工程**（默认是“演示工程”）。
2. 点击工具栏（或右侧“提示项”面板标题旁）的 **⇄ 跨工程移植** 按钮；
   先用“＋ 新工程”新建一个目标工程（如“目标工程”）也可。
3. 在弹窗中勾选一个或多个提示项（可点“全选 / 清空”），在“目标工程”
   下拉框选择另一个工程，在“落点”填入非负整数毫秒（如 `2000`），
   点击 **提交移植**。
4. 成功后弹窗列出本次 **原 ID → 新 ID** 对应；点击“关闭”即自动切换到
   **目标工程**：移植项在时间轴上以 **青色描边（渐变色块）/ 青色角标
   （立即切换）** 标出，色块右端标注“原#编号”，编辑面板显示其原工程 /
   原编号，侧栏“提示项”顶部横幅再次给出落点、平移量与完整 ID 对应表。
   片段最早实际起步正好对齐落点（如 `2000ms`），各项之间的相对时差、
   渐变时长、引用开始/结束语义与源工程一致。
5. 若提交被拒绝（空选择 / 提示项或工程无效 / 源目标相同 / 与目标工程
   已有项同通道同刻冲突），弹窗内显示原因，源工程与目标工程数据均不变，
   可调整后重新提交。

也可以直接用 API 验证（演示工程 id 为 `1`）：

```bash
# 新建目标工程
curl -s -X POST http://localhost:8000/api/projects \
  -H 'Content-Type: application/json' -d '{"name":"目标工程"}'
# 把演示工程的 #4、#5（自动带上其上游 #1、#3）移植到工程 2，落点 2000ms
curl -s -X POST http://localhost:8000/api/projects/1/transplant \
  -H 'Content-Type: application/json' \
  -d '{"target_project_id":2,"item_ids":[4,5],"landing_ms":2000}'
# 随后打开目标工程即可看到移植项；或直接查看详情中的实际时刻
curl -s http://localhost:8000/api/projects/2
```

精确时刻求值接口（演示工程中 `面光1·CH1` 为 0→180 的 2000ms 渐变，
任意精度的小数时刻都原样求值，不做固定位数舍入）：

```bash
curl 'http://localhost:8000/api/projects/1/eval?t=1.5'         # 0.135 = 27/200
curl 'http://localhost:8000/api/projects/1/eval?t=5/3'         # 也接受分数
curl 'http://localhost:8000/api/projects/1/eval?t=1.23456789'  # 8 位小数原样精确求值
```

最后一条返回的 `time_ms` 回显为 `1.23456789`，`面光1·CH1` 的精确值
`raw` 为 `1111111101/10000000000`（即 180 × 1.23456789 / 2000），与直接
对同一时刻求值完全一致；页面播放头停在同一时刻时读数相同。

SQLite 数据库保存在 Docker 卷 `lights-data`（容器内 `/data/lights.db`）中，
重启 / 重建容器数据不丢失。首次启动会自动建表并写入一个“演示工程”
（包含引用、立即切换与渐变被打断的例子）。

停止：

```bash
docker compose down          # 保留数据
docker compose down -v       # 同时删除数据卷
```

## HTTP API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/projects` | 工程列表 |
| POST | `/api/projects` | 新建工程 `{"name": "..."}` |
| GET | `/api/projects/{id}` | 工程详情（含各项实际时刻、打断关系、引用闭包） |
| POST | `/api/projects/{id}/items` | 新增提示项 |
| PUT | `/api/projects/{id}/items/{item_id}` | 修改提示项（整项替换） |
| DELETE | `/api/projects/{id}/items/{item_id}` | 删除提示项（被引用时 409） |
| POST | `/api/projects/{id}/transplant` | 跨工程片段移植，见下 |
| GET | `/api/projects/{id}/eval?t=<ms>` | 对**任意非负小数（或分数）毫秒**时刻求全部通道值，如 `t=1.5`、`t=5/3` |

提示项 JSON 示例：

```json
// 绝对时间起步
{"fixture": "面光1", "channel": 1, "target": 180, "duration": 2000,
 "start_mode": "abs", "start_ms": 0}

// 引用 #1 的结束 + 0ms 起步
{"fixture": "面光1", "channel": 1, "target": 60, "duration": 1500,
 "start_mode": "ref", "ref_id": 1, "ref_edge": "end", "ref_offset": 0}
```

跨工程移植请求（`POST /api/projects/{源工程id}/transplant`）：

```json
{"target_project_id": 2, "item_ids": [4, 5], "landing_ms": 2000}
```

`item_ids` 为源工程中勾选的提示项；后端先解析源工程引用得到各项实际起步，
把所选项及全部上游引用项作为一批（共享祖先只移植一次），令批次最早实际起步
加上平移量后恰好等于 `landing_ms`（非负整数毫秒），再以“依赖在前”的顺序逐项
分配新 ID 并重接引用（引用开始/结束边与偏移、渐变时长不变）。成功 `201`
返回 **目标工程完整详情** 外加：

```json
{
  "id": 2, "name": "目标工程", "items": [ ... ],
  "id_map": [{"source_id": 1, "new_id": 8}, ...],
  "source_project_id": 1, "landing_ms": 2000, "shift_ms": 2000
}
```

拒绝时不返回 `id_map`：`item_ids` 为空 / 字段非法（含负落点）→ 422；源工程
不存在 → 404；目标工程不存在、源目标相同、提示项不属于源工程（无效 ID）→ 400；
全部写入后对 **合并后的目标工程** 做整工程校验，同通道同刻冲突 → 409。任一
拒绝都在同一事务内回滚，源工程与目标工程原有项字段均不变。

求值响应同时返回四舍五入后的显示值 `value` 与精确值 `raw`（分数字符串），
以及此刻决定该通道值的提示项 `active_item_id`；回显的 `time_ms` 为整数时刻
返回整数、小数时刻返回数值（如 `1.5`）。非法 / 为空 / 负数的 `t` 返回 422。
例：0→100 的 1000ms 渐变在 `t=5` 时 `raw` 为 `1/2`、`value` 为 `1`（恰好 0.5
向上）；若错误地截断为整数，`t=5` 与 `t=4.95` 的读数便会与直接求值不一致。

## 设计说明

- 提示项的时刻以非负整数毫秒表示；引用图为 DAG，实际时刻在保存时按记忆化递归
  （等价于拓扑序）整体重算。
- 但求值时刻可以是 **任意非负小数毫秒**：`/eval?t=` 按原始文本解析为
  `fractions.Fraction`（也接受 `5/3` 这样的分数），引擎全程分数运算、
  不经过任何 `int` 截断；前端播放头（requestAnimationFrame 的帧间时间本身就是
  小数）、拖动与跳转同样 **原样** 传递该时刻——回显到跳转输入框、请求去重、
  播放节流的末次补发都使用同一个未舍入的值，不再做任何固定位数（如六位小数）
  舍入；播放节流只限制请求频率、不改写时间，暂停 / 跳转 / 拖动结束都会再发
  一次即时请求，保证读数与直接对该时刻求值一致。整数时刻行为与以前完全一致。
- 前端求值按“工程 id + 数据代次（`evalGen`）+ 时刻”的复合键去重：只有三者
  完全相同才复用缓存。切换工程或写操作成功返回后立即提升代次，因此同一播放头
  时刻也必然重新求值；同一时刻的重复调用仍被合并，播放时不会多发请求。进行中
  的请求在响应到达时核对（工程, 代次）：工程已切换或数据已变化的旧响应直接
  作废，绝不写入界面；只有在当前时刻尚无在途求值、也无缓存读数时才借单飞队列
  补发一次（旧请求成功 / 失败均如此），避免冗余请求。切换工程（含空工程）与
  写操作成功后会先清空旧读数再渲染，防止已删除的通道残留；当前工程的求值失败
  时清空读数、保留错误提示；保存失败走表单错误提示分支，不应用返回、不动数据
  代次与读数，因此界面仍是原工程读数。
- 连续切换工程时，详情请求按递增序号（`openSeq`）定序：每次 `openProject`
  领取新序号，响应到达时序号仍最新才允许应用——仅比较工程 id 无法识别
  A→B→A 中较早的 A 请求，序号可以。被超越的详情响应无论成功或失败都直接
  丢弃，不改动当前页面；最后一次选择加载失败时弹出错误提示，并把工程上下文
  （`projectId`、下拉框、本地记忆）回退到仍在屏上的工程，泳道、编辑区与后续
  求值始终描述同一个工程，不会留下错配读数。此外 `requestEval` 只在“屏上
  工程与所选工程一致”时才发请求：详情在途（或加载失败）期间的播放 / 拖动 /
  跳转不会把下一个工程的通道求到当前泳道上，有效详情落地后由它按当前时刻
  补发求值，页面最终只呈现最后一次选择的工程及对应时刻读数。
- 读数的时效按“**屏上工程 + 数据代次 + 播放头时刻**”三者共同判断
  （`readoutTime` 记录屏上读数实际所属时刻）：详情在途、求值被挂起期间，
  读数只在播放头仍停在原时刻时继续有效；播放头一旦离开（拖动 / 跳转 /
  播放），`requestEval` 的挂起分支立即调用 `withdrawStaleReadout()` 撤下
  旧时刻读数——而不是等详情成败后再处理，避免旧读数停在新播放头旁。
  详情成功落地会清空旧读数并按当前时刻求值；详情失败、上下文回退到屏上
  工程时（不恢复 `evalGen`，以免切换前的缓存 / 在途读数蒙混通过新鲜度
  校验），同样先撤下旧时刻读数再 `requestEval(true)` 对当前时刻补算，
  因此“A 已显示 t0 → 选 B（未返回）→ 跳到 t1 → B 失败回退 A”最终显示的是
  A@t1，绝不会把 A@t0 留在 t1 旁。求值响应到达时除工程 / 代次外还比对
  请求时刻与当前播放头：播放头移动后才到的旧时刻响应（成功不写屏、失败
  不清屏也不弹错）一律作废，并在当前时刻既无缓存也无在途求值时经单飞
  队列补发一次；当前工程当前时刻的求值失败则清空读数、弹出提示，
  `readoutKey` 保持 `null`，之后的播放 / 跳转不会被去重跳过。
- 渐变值使用 Python `fractions.Fraction` 精确计算，因此多次打断 / 接续不会
  累积浮点或显示舍入误差；显示时才做半值向上舍入。
- 写操作先在事务内写入“候选结果”，再对整个工程重新校验，任何错误都会回滚，
  保证“失败不得改变原工程”。
- 跨工程移植在纯逻辑层（`engine.plan_transplant`）先解析源工程引用得到各项
  **实际起步**，再求“所选项 + 全部上游引用”的祖先闭包（共享祖先只出现一次），
  并给出依赖在前的批次顺序（被引用者一定排在引用者之前）；平移量取
  `落点 − 批次最早实际起步`，只加到绝对时间项上，引用项保留边（开始/结束）与
  偏移，因此相对时差、渐变时长与引用语义天然保持。端点在同一事务中按该顺序
  逐项写入目标工程：写到引用项时其祖先已经落库、新 ID 已知，引用直接重接到
  真实新 ID，不需要为“尚未写入的祖先”猜测 ID；随后对 **合并后的目标工程**
  执行与单项写入相同的整工程校验（`resolve`），同通道同刻冲突按合并结果裁决，
  任何失败都回滚整批插入，源工程全程只读、目标工程原有项字段不变。响应额外
  携带 `id_map`（原 ID → 新 ID）、`landing_ms`、`shift_ms`，前端据此在目标
  时间轴标记移植项并展示对应关系；该标记只是视图状态，切换工程即清除，不落库。
